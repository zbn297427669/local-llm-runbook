# 思考预算对照案例：鹈鹕骑自行车

同一提示词、同一台机器、同一份模型，只改**思考预算**，六种配置各生成一个
单文件 HTML 页面。用来回答一个具体问题：

> 本地模型比在线慢好几倍，是算得慢，还是想得多？

**答案是后者：默认配置里有 85% 的输出 token 是思考，代码只占 15%。**

---

## 提示词

```
Write a complete single-file HTML page with canvas: a pelican riding
a bicycle, animated. All code in one file, no explanation.
```

## 实测结果

| 配置 | 耗时 | 输出 token | 思考字符 | 代码字符 | 函数 | 动画相位 | 近/远端建模 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | :---: |
| **medium** | **57.4 s** | 4,885 | 5,282 | 8,231 | 7 | 3 | **✅** |
| none | 37.4 s | 3,944 | 0 | 9,794 | 9 | **0** | ❌ |
| budget 2048 | 68.7 s | 6,277 | 7,242 | 10,668 | 9 | 4 | ❌ |
| budget 4096 | 87.5 s | 8,013 | 13,572 | 9,174 | 8 | 3 | ❌ |
| budget 8192 | 126.1 s | 11,143 | 23,902 | 8,257 | 6 | 3 | ❌ |
| default（high） | **311.7 s** | 27,887 | 71,608 | 7,925 | 4 | 3 | ❌ |

## 文件

扫描那一轮（同一批次，可直接横向对比）：

| 文件 | 对应配置 |

| `pelican-medium.html` | `reasoning_effort: medium` |
| `pelican-budget-2048.html` | `reasoning_budget_tokens: 2048` |
| `pelican-budget-4096.html` | `reasoning_budget_tokens: 4096` |
| `pelican-budget-8192.html` | `reasoning_budget_tokens: 8192` |
| `pelican-default-high.html` | 默认（high） |

早期零散测的两个文件，**和上表不是同一轮**，结果有随机差异，仅作参考：

| 文件 | 说明 |
| --- | --- |
| `pelican-default.html` | 早期默认配置。函数 13 个、相位 4 个、有近/远端建模 —— 比扫描轮的 default 更好，说明**单次样本不可比** |
| `pelican-nothink.html` | 早期 none。代码 9,048 字符，扫描轮是 9,794 |

## 怎么看结构

不是看字符数，看三样东西：

| 指标 | 含义 |
| --- | --- |
| **动画相位** | `sin(t * K)` 里不同 K 的个数。只有 1 个 = 整体摆动；3–4 个 = 身体/头/尾/翅膀各自独立 |
| **近/远端建模** | 有没有分别计算远侧和近侧踏板位置（`pedalFar` / `pedalNear`），让两条腿交替 |
| **函数拆分** | 有没有把腿、身体、翅膀拆成独立函数，而不是平铺在 canvas 调用里 |

**`medium` 是唯一同时具备「多相位 + 近/远端建模」的**，所以它不只是快，结构也最完整。

## 三个反直觉的发现

### 1. 思考越多，代码反而越短

```
budget 2048 → 10,668 字符
budget 4096 →  9,174 字符
budget 8192 →  8,257 字符
default     →  7,925 字符
```

想得越多，越倾向于**简化**，而不是做得更细。这和「想得多 → 做得细」的直觉相反。

### 2. `none` 函数最多，但没有动画分层

`pelican-none.html` 有 9 个函数、代码 9,794 字符，但**动画相位是 0**。
它是静态构图加整体位移，不是分层的动画。**看起来代码更多，实际结构更弱。**

### 3. `default` 花 8.4 倍时间，结构分最低

| | default | medium |
| --- | ---: | ---: |
| 耗时 | 311.7 s | **57.4 s** |
| 函数 | 4 | 7 |
| 近/远端建模 | ❌ | ✅ |

**快了 5.4 倍，结构还更好。**

## 一个写这份记录时的自我更正

我一度从**单次**样本得出「关掉思考代码反而更多」，还据此分析了原因。
重复测后发现那是随机波动——同一配置两次生成差 24%（11,239 vs 9,048 字符）。

**唯一稳定且量级巨大的差异是速度：5.4 倍。**
结构上的差异需要多次重复才能判断，单次对比会骗人。
