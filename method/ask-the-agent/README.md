# 追问清单 · ask the agent

> 这个项目最值得带走的东西不是任何参数，是四个问句。

## 为什么需要它

Agent 很少「不会做」。它更容易**停下来**——在一个说得通的答案出现的时候。

这个项目里记录的四次停摆，没有一次是能力问题：同一台机器、同一个 Agent，它后来读引擎日志反推参数、把一个假设跑完量出数字，都做得很好。它只是在没人追问的地方，合理地停了。

所以这份清单不教你怎么用 Agent，教你怎么问它。

## 四条检查

| # | 盲点 | 它当时的样子 | **该问的那一句** |
|---|---|---|---|
| ① | 只验证「改动生效」，不验证「改动正确」 | 改完看到数字变好就收 | **「这个结论覆盖了哪些配置？没覆盖的那些怎么办？」** |
| ② | 有现成的审计工具，却不主动用 | 工具在手上，没跑 | **「你有审计工具吗？先跑一遍，再给我结论。」** |
| ③ | 问题定义停在参数上 | 默认「调优 = 改参数」 | **「除了参数，还有什么在影响这件事？有没有不是参数的选项？」** |
| ④ | 第一个说得通的解释一出现就停 | 界面卡 → 内存够 → 没有然后 | **「还有别的解释吗？怎么排除它们？」** |

## 四条的共同点

都不是「能不能做到」，而是**「什么时候停」**。

停的时机由三件事决定：任务怎么提、验证标准是什么、有没有人在追问。**不主要由模型能力决定。**

所以：

- 换一个更强的模型，如果没人问 ①，它照样只验证生效。
- 加一份更强的提示词，如果没写清 ③ 的边界，问题定义还是收到参数上。
- 唯一稳定有效的，是有人在旁边问一句——这也是这个项目的结论：**人能问的，正好是它看不见的。**

## 怎么用

1. **事后复盘**：把上面四句逐条对着 Agent 的结论问一遍，看它能不能答上来。答不上来的那条就是漏的。
2. **事前写进任务**：把这四句作为验收条件写进提示词（[`../../strata/skills/strata-tune/SKILL.md`](../../strata/skills/strata-tune/SKILL.md) 就是这么做的）。
3. **交接给下一个人**：四句比「你注意点」有用得多。

## 一个反例，别把这套用成怀疑一切

在同一个项目里，这个 Agent 做了两件很难的事：从引擎日志反推出两个未公开的参数；把一个假设完整跑完并量出数字。

**它的产出是可信的。可疑的是它的停止条件。**

如果每一条结论都要人重新验一遍，那用 Agent 就没意义了。这份清单的用法是**抽查加追问**，不是全量复算。

## 还没验证的

- 这四条是从**一次**完整项目里提炼的，不是统计结论。
- **没有做跨模型对照**：同样的四句问法，换成别的模型会不会表现不同，这里没有数据。
- 如果要补，做法是：同一任务、同一套 harness、不同模型，记录「谁主动审了自己的结论」。这是这个仓库下一步最想补的实验。
